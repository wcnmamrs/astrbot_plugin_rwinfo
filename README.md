# 铁锈查房 (astrbot_plugin_rwinfo)

> AstrBot 插件 · 群内自动识别铁锈战争房间号并安排探针机器人查房回传

[![AstrBot](https://img.shields.io/badge/AstrBot-%E6%8F%92%E4%BB%B6-blue)](https://github.com/Soulter/AstrBot)
[![Python](https://img.shields.io/badge/Python-3.9%2B-green)](https://www.python.org/)
[![License](https://img.shields.io/badge/License-MIT-yellow)](LICENSE)

识别群消息中的铁锈战争（Rusted Warfare）房间号，安排探针机器人（`<前缀>探针01~99`）进入房间查询并回传：房间版本 / 地图 / 资金 / 迷雾 / 禁核 / 倍率 / 模式 / 单位上限 / 默认单位 / 共享控制 / 旁观 / 队伍锁定 / 人数 / 玩家列表 / 房间短号。

协议逆向细节见 [PROTOCOL.md](PROTOCOL.md)，版本变更见 [CHANGELOG.md](CHANGELOG.md)。

---

## 功能特性

- 自动识别房号并查房：数字房（`o`/`q`/`r`/`s` + 数字）与字母房，≥3 字符；
  查不到的自动静默丢弃
- `/铁锈列表` 分页浏览，`/铁锈查房 <序号>` 直接查详情
- 房间信息：版本 / 地图 / 资金 / 迷雾 / 禁核 / 倍率 / 模式 / 单位 / 人数 / 玩家列表 / 短号
- 探针名可配置，被过滤时自动重试
- 自动撤回、房号冷却、探针池并发（`探针01~99`）
- 进房推广（默认关）
- 黑白名单权限控制，按用户与群分别配置
- 内置协议探针，无第三方依赖

## 安装

AstrBot 插件商店搜索安装，或在 WebUI 中安装：

1. 打开 AstrBot 管理面板，进入插件管理
2. 粘贴仓库地址 `https://github.com/wcnmamrs/astrbot_plugin_rwinfo` 自动拉取，或上传打包 zip
3. 安装后启用即可

`room_info.py` 缺失或接口过旧时，会从仓库下载补齐。

## 指令

指令分两类权限，**互不重叠**：

- **查询类**（列表 / 查房 / 翻页 / 帮助）：对所有人生效，是否放行由插件自己的
  白名单 / 黑名单 / 混合模式与私聊策略决定。没配名单时群里所有人都能用。
- **配置与诊断类**：仅 AstrBot 管理员可用（`PermissionType.ADMIN`）。

| 指令 | 权限 | 说明 |
|------|------|------|
| `/铁锈查房帮助` | 所有人 | 显示指令菜单。别名 `/铁锈查房菜单` `/铁锈帮助` `/rwhelp` |
| `/铁锈列表 [参数]` | 名单放行 | 分页浏览房间。别名 `/房间列表` `/铁锈房列表` `/rwlist` |
| `/铁锈下一页` `/铁锈上一页` | 名单放行 | 房间列表翻页 |
| `/铁锈查房 <序号\|房号\|IP:端口>` | 名单放行 | 显式查房。序号来自最近一次列表，房号如 `r5132` / `hytvvi`，也可直接填 `IP` 或 `IP:端口` |
| `/铁锈探针时解 <5位后缀>` | 所有人 | 还原探针进房时间。例 `/铁锈探针时解 fkhk3`，也可直接贴完整探针名 `<前缀>探针01_fkhk3` |
| `/铁锈全局解析 开\|关` | 管理员 | 全局解析总开关，默认开 |
| `/铁锈模式 白\|黑\|混合` | 管理员 | 名单模式，默认黑。混合模式下 `@` 优先于 `#`，同名互斥 |
| `/铁锈白名 +@用户ID` `/铁锈白名 +#群号` | 管理员 | 白名单增删，无参数打印列表 |
| `/铁锈黑名 +@用户ID` `/铁锈黑名 +#群号` | 管理员 | 黑名单增删，无参数打印列表 |
| `/铁锈私聊策略 白\|黑` | 管理员 | 混合模式私聊默认策略 |
| `/铁锈私聊开关 开\|关` | 管理员 | 是否启用私聊查房，默认开 |
| `/铁锈玩家列表 开\|关` | 管理员 | 是否显示玩家列表，默认关 |
| `/铁锈重试 [0-10]` | 管理员 | 探针名被过滤时的重试次数 |
| `/铁锈压缩 [范围]` | 管理员 | 消息折叠范围 |
| `/铁锈撤回 [列出\|+\|-\|重置]` | 管理员 | 自动撤回配置。`列出` 看全部、`+`/`-` 增删、`重置` 清空；不带参数看本会话。`+ *:60` 会展开到所有已识别的群 |
| `/铁锈查房调试` | 管理员 | 打印运行时状态：会话、撤回、探针池、列表缓存、配置、官机 |
| `/铁锈查房调试菜单` | 管理员 | 查看可改的内部数值与改法 |
| `/铁锈官机探测` | 管理员 | 输出官方通道现场结构（只读） |
| `/铁锈官机测试` | 管理员 | 发一条 Markdown 样例验证通道 |

发送未识别的 `/铁锈xxx` 时自动返回帮助菜单。

### 房间列表

```
/铁锈列表 [页码]|[筛选]|[搜索 关键词]|[刷新]
/铁锈下一页 / 铁锈上一页
```

**筛选词**

| 参数 | 说明 |
|------|------|
| `房间中` / `游戏中` | 房间状态 |
| `满` / `不满` | 人数是否已满 |
| `真人` / `官方` | 数据来源 |
| `搜索 关键词` | 按房主名 / 地图名模糊搜索 |
| `刷新` | 忽略缓存重新抓取 |

**页码**为纯数字，`2` 表示第 2 页。参数可任意组合，如 `/铁锈列表 房间中 真人 2` 表示「房间中 + 真人房」筛选结果的第 2 页。

**筛选继承规则**

| 用法 | 行为 |
|------|------|
| `/铁锈列表`（不带参数） | 全新查询，清空所有筛选 |
| `/铁锈列表 2`（仅页码） | 沿用上次筛选，跳到第 2 页 |
| `/铁锈下一页` `/铁锈上一页` | 沿用上次筛选翻页 |
| `/铁锈列表 房间中`（给了筛选词） | 整体替换旧筛选，只用本次条件 |

筛选状态按 QQ 号（群 + 用户）隔离；**页码永不过期**，插件重启后仍可从
上次页码继续翻页（翻页状态通过 AstrBot KV 持久化）。

展示格式（每页默认 5 条）：

```
1. 萧逸  1/10  房间中
   地图：Crossing Large (10p)

2. SERVER  2/10  房间中
   地图：Two Sides Remake (10p)
```

房名为 `Unnamed` 时优先展示房主名（CSV 第 1 列是房名，第 7 列才是房主名）。

### 查房

```
/铁锈查房 <序号|房号|IP:端口>
```

| 参数形式 | 说明 | 例子 |
|---|---|---|
| 序号 | 取自最近一次 `/铁锈列表` 的编号（按当前页，映射 10 分钟有效，过期自动静默重建） | `/铁锈查房 2` |
| 数字房 | `o` `q` `r` `s` + 数字，至少 3 位 | `/铁锈查房 r5132` |
| 字母房 | 其他字母开头 + 纯字母，至少 3 位 | `/铁锈查房 hytvvi` |
| 直连 | `IP` 或 `IP:端口`（端口省略按 5123） | `/铁锈查房 45.76.27.30:5125` |

**权限**

`/铁锈列表` 与 `/铁锈查房` 都按黑白名单放行：默认 `black` 模式且名单为空时，
群里所有人都能用；管理员可用 `/铁锈模式`、`/铁锈白名`、`/铁锈黑名` 收窄范围。
被拦截时会明确回复原因，不会静默丢弃。

**自动触发与显式查房的区别**

| | 自动识别（群内发房号） | 显式查房（`/铁锈查房`） |
|---|---|---|
| 允许 IP 直连 | 否 | 是 |
| 查询失败 | **静默**，不发消息 | **回传原因** |
| 目的 | 避免英文单词误报刷屏 | 用户明确指定，必须给出结果 |

自动触发时只有「房间确实存在」类的原因才回传（房间已满 / 已锁定 / 游戏已开始 / 被封禁），
「房间不存在 / 中继未响应 / 地址不可达」等一律静默丢弃。

`房号冷却秒`（默认 10）防止同一会话反复发同一个房号刷请求，
按会话隔离 —— A 群查过的房不影响 B 群。

数据源两个，合并后真人房优先、房间中优先、人数降序：

| 源 | 说明 |
|----|------|
| Q Room List | `https://www.rtsbox.cn/api/paiwei/room_last.php`，真人房，含房主名 / 地图名 / 人数 / 状态 |
| Official | 官方 `masterserver` 的完整列表（含 Auto Server 与中继房），排在真人房之后 |

列表只保留可查的真人房：链接条目、字段非法、空置入口、推广话术、
以及人数超出游戏上限（房间上限最大 100）的刷数据条目都会被跳过。

缓存：房间数据全局共享一份（60 秒滑动续期）；翻页与筛选状态按「群 + 用户」
隔离并**通过 KV 持久化，页码永不过期**——插件重启后仍能从上次页码继续。
「序号 → 房间」的映射 10 分钟有效，过期后按原页码静默重建。

## 配置

由 AstrBot 框架自动持久化，可通过 WebUI 修改，也支持指令修改后即时保存。

| 配置项 | 说明 |
|--------|------|
| `global_enabled` | 全局解析开关，默认 true |
| `mode` | 名单模式：`white` / `black` / `mixed`，默认 black |
| `白名单` / `黑名单` | 白/黑名单列表（用户/群） |
| `混合_白名单` / `混合_黑名单` | 混合模式独立名单，切换回白/黑模式时原名单保持原状 |
| `混合_私聊策略` | 混合模式私聊默认策略：`white`=不在白名单拦截 / `black`=在黑名单拦截 |
| `私聊启用` | 是否启用私聊查房处理，默认 true |
| `debug` | 是否开启调试日志 |
| `官Q模式` | 是否走 QQ 官方机器人排版（Markdown 卡片 + 按钮），默认 false。第三方机器人保持关闭。按钮只挂在**查房结果**和**房间列表**上，指令回执不挂 |
| `压缩范围` | 折叠范围：`none` / `room` / `list` / `diag` / `help` / `all`，默认 none。第三方机器人改用合并转发卡片折叠，官方机器人用 Markdown 代码块 |
| `指令唤醒词` | 必须与 AstrBot 主配置的唤醒词一致，默认 `/` |
| `显示项目地址` | 是否展示项目地址，默认 true。官方机器人=卡片底部按钮；第三方机器人=内容消息末尾虚线小字（指令回执、调试输出不显示） |
| `调试菜单` | 调试指令是否支持分类查看，默认 true |
| `max_players_display` | 玩家列表最多显示人数，超过则折叠，默认 10 |
| `show_players` | 是否显示玩家列表，默认 false |
| `retry_times` | 探针名被过滤时的重试次数，0-10，默认 3 |
| `list_page_size` | 房间列表每页条数，默认 5（仅控制单条消息长度，不限房间总数） |
| `list_default_full` | 房间列表默认人数筛选，`hide` 表示隐藏人满房间 |
| `probe_max_per_msg` | 单条消息最多召唤的探针数，默认 5（1-20） |
| `探针名前缀` | 探针名 `<前缀>探针01` 的前缀部分，默认 `ABAB`。限 1-4 个字符，只允许中英文/数字/`_`/`-`，非法字符自动丢弃，超长自动截断，清洗后为空回退默认值 |
| `冷却提示` | 房号仍在冷却时是否回一条提示，默认 false（完全静默） |
| `机器人QQ号` | 仅用于合并转发的发送者 uin；留空自动读取 |
| `推广开关` | 进房后是否发一条项目地址，默认 false |
| `推广冷却秒` | 同一房间的推广冷却，默认 180（3 分钟）。按房间独立计算，换房间立刻可发 |
| `bin_cleanup_enabled` | 是否在插件运行期间定时清理 bin 缓存，默认 true |
| `bin_cleanup_interval_hours` | 清理检查间隔（小时），默认 24 = 一天一次，最小 1 |
| `bin_cleanup_max_age_hours` | 只清理超过该小时数的 bin 缓存，默认 1 小时 |
| `撤回` | 自动撤回配置，格式 `key:延迟秒`，写入即启用，删掉即关闭。key 前缀区分类型，例 `#123456:60` / `@3856554669:30` / `*:60` |

**撤回配置怎么改**

| 指令 | 作用 |
|---|---|
| `/铁锈撤回` | 查看本会话生效配置 |
| `/铁锈撤回 列出` | 列出全部配置 |
| `/铁锈撤回 + #群:60 @qq:30` | 添加/修改（可跟多条） |
| `/铁锈撤回 - #群 @qq` | 删除（可跟多条） |
| `/铁锈撤回 重置` | 清空全部 |
| `/铁锈撤回 + *:60` | 展开到所有已识别的群 |
| `/铁锈撤回 开\|关\|30` | 快捷设置本会话 |

`*` 是通配符：写进配置时会**展开成每个已知群的具体条目**（不重复添加），
这样你能在 `列出` 里看到它实际覆盖了哪些群。

`关` 在**只是继承了 `*` 默认**的群里同样有效：它不会去动 `*`，而是给本群
写一条 `#群号:off` 显式关闭记录（`列出` 里显示为「关闭（覆盖默认）」），
要恢复就再发 `开` 或直接给秒数。

**关于会话隔离**

以下状态全部按「会话 + 用户」隔离，跨群互不可见：

| 状态 | key 格式 | 说明 |
|---|---|---|
| `/铁锈列表` 翻页与筛选 | `g#群号@QQ号`（群）/ `p@QQ号`（私聊） | 包含该页序号的真实地址缓存，串号会导致查错房 |
| 房号冷却 | `会话key\|房号` | A 群查过的房不影响 B 群 |
| 自动撤回配置 | `#群号` / `@用户ID` / `*` | 单一列表，前缀区分群与用户，群聊可用 `*` 作全局默认 |

### 项目地址展示

`显示项目地址` 默认开启，两种平台的表现不同：

| 平台 | 展示方式 |
|---|---|
| 官方机器人（`官Q模式` 开） | 查房结果、房间列表的卡片底部多一个「项目主页」跳转按钮，正文里不出现地址文字 |
| 第三方机器人（`官Q模式` 关） | **查房结果、房间列表、帮助末尾多一行虚线小字地址** `⋯⋯ https://github.com/...`；指令回执、调试输出、报错不追加 |

地址是硬编码常量，不提供配置修改。关掉 `显示项目地址` 则两者都不展示。

### bin 缓存清理

`room_info.py` 每次查到房间信息后，会把原始 106/115 报文写到
`server_info_<版本>_<目标>_<时间戳>.bin`，用于排查协议问题。这些文件只在调试时有用，
长期运行会不断堆积。

清理策略：**插件启动后开始计时，每隔 `bin_cleanup_interval_hours`（默认 24 小时）
检查一次，删除修改时间超过 `bin_cleanup_max_age_hours`（默认 1 小时）的 bin 文件。**

几个实现要点：

- 清理固定作用于 `room_info.py` 所在目录（`BIN_DIR`），不依赖当前工作目录；
  写入端也用同一路径，避免"写在 A 目录、清的是 B 目录"。
- 实际清理跑在独立子进程（`room_info.py --cleanup-bins`），不阻塞事件循环。
- 清理失败不会终止循环，下一轮会重试。
- 插件卸载（`terminate`）时会取消该循环，不留后台任务。
- 若加载时事件循环尚未就绪，会在首条消息到达时惰性补启，不影响正常使用。
- 间隔与阈值都有 60 秒下限保护，防止误配成 0 后疯狂执行。

也可以手动清理：

```bash
python3 room_info.py --cleanup-bins               # 清理 1 小时前的
python3 room_info.py --cleanup-bins --max-age 600 # 清理 10 分钟前的
```

## 消息示例

群内有人发：

```
ADMIN: Other players can type HLBIFZ in 'direct join' to connect to this room.
```

机器人自动回复：

```
房间版本：1.15
地图名称：Crossing Large (10p)
初始资金：4000¤[1x倍率]
初始禁核：未禁用核蛋蛋
初始迷雾：重雾
地图模式：遭遇战
默认单位：常规模式（1个建造者）
单位上限：1100
共享控制：否
允许旁观：是
队伍锁定：否
当前人数：2/10
ID：hlbifz
 玩家列表:
  A1: abab
  A3 (AI): AI - Hard
```

探针名被过滤时先回进度再重试：

```
[房间查询] 重试中(1/3)
[房间查询] 重试中(2/3)
[房间查询] 重试中(3/3)
```

无法加入时返回翻译后的原因：

```
[房间查询失败] 房间已满，无法加入
[房间查询失败] 游戏已经开始
[房间查询失败] 房间已锁定
```

## 命令行工具

```bash
python3 room_info.py R5132                # 查询中继房间

python3 room_info.py R5132 --show-players # 显示玩家列表
python3 room_info.py R5132 --debug        # 调试输出
```

## 说明

- 查询通过子进程调用 `room_info.py` 完成，互不干扰，查询完自动发 111 退出，不占房间位置
- 私聊按发送者用户ID进名单校验；群聊同时校验 `#群号` 与 `@用户ID`（用户黑名单在群聊同样生效）
- 玩家列表按槽位顺序显示，空名字显示为 `(空)`
- 房间处于「开局后返回战役室」状态时服务器不更新状态，此时真人可进入但探针会被拒绝，属游戏机制
- 本插件仅供学习与娱乐，请勿用于恶意刷房或干扰他人游戏

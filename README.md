# 铁锈查房 (astrbot_plugin_rwinfo)

> AstrBot 插件 · 群内自动识别铁锈战争房间号并安排探针机器人查房回传

[![AstrBot](https://img.shields.io/badge/AstrBot-%E6%8F%92%E4%BB%B6-blue)](https://github.com/Soulter/AstrBot)
[![Python](https://img.shields.io/badge/Python-3.9%2B-green)](https://www.python.org/)
[![License](https://img.shields.io/badge/License-MIT-yellow)](LICENSE)

识别群消息中的铁锈战争（Rusted Warfare）房间号，安排探针机器人（ABAB探针01~99）进入房间查询并回传：版本 / 地图 / 资金 / 迷雾 / 禁核 / 倍率 / 模式 / 单位上限 / 默认单位 / 共享控制 / 旁观 / 队伍锁定 / 人数 / Mod / 玩家列表。

协议逆向细节见 [PROTOCOL.md](PROTOCOL.md)，版本变更见 [CHANGELOG.md](CHANGELOG.md)。

---

## 功能特性

- **自动识别房号**，一律尝试，成功才发送，查不到自动静默丢弃，无需过滤词表
  - 数字房：`o` `q` `r` `s` + 数字，如 `r5132`、`s1024`、`o9999`、`q7777`
  - 字母房：其他字母开头 + 纯字母，如 `hytvvi`、`aabcde`、`babc`
  - 两种形态均要求整串 ≥ 3 字符；纯数字、混合格式（`a1b2c3`）、URL 片段、`u_` 前缀不识别
- **房间列表**：`/铁锈列表` 分页浏览
- **从列表直接查房**：`/铁锈查房 <序号>` 复用列表结果，一键查详情
- **失败原因中文翻译**：房间已满、游戏已开始、房间已锁定等返回明确提示
- **探针名被过滤自动重试**：可配置次数（默认 3 次），多条房号时重试名带各自编号避免串号
- **自动撤回**：房间信息与重试进度可自动撤回，按群/私聊独立配置，默认关
- **探针池**：ABAB探针01~99 并发复用，单条消息最多处理 5 个房号（可配置 `probe_max_per_msg`）
- **房号冷却**：同一房号 10 秒内不重复查询
- **权限控制**：全局开关 + 白/黑名单，支持按用户（`@用户ID`）与群（`#群号`）分别控制
- **完全自包含**：内置协议探针，无第三方依赖、无绝对路径硬编码

### 房号识别依据

客户端（`ae.smali` 行 7107~7180）对不含 `:` `.` `/` `\` 的纯房号统一转换为 `<首字母>.relay.corrodinggames.com/<房号>`，因此首字母不限于 r/s/h。

实测中继可用性：

| 首字母 | 中继 | 状态 |
|--------|------|------|
| a / b / h | 官方 Relay US1 / US2 / ASIA2 | 可连 |
| o / q / r / s | RELAY-CN / Fancy-CN / Tiexiu.xyz | 可连 |
| c / g / j / v | 有域名但端口未开放 | 连接失败 |
| 其余 | 无 DNS 记录 | 解析失败 |

## 安装

AstrBot 插件商店搜索安装，或在 WebUI 中安装：

1. 打开 AstrBot 管理面板，进入插件管理
2. 粘贴仓库地址 `https://github.com/wcnmamrs/astrbot_plugin_rwinfo` 自动拉取，或上传打包 zip
3. 安装后启用即可

若插件目录内没有 `room_info.py`，会自动回退查找上级目录。

## 指令

除帮助外，其余指令默认仅管理员可用（`PermissionType.ADMIN`）。

| 指令 | 权限 | 说明 |
|------|------|------|
| `/铁锈查房帮助` | 所有人 | 显示指令菜单。别名 `/铁锈查房菜单` `/铁锈帮助` `/rwhelp` |
| `/铁锈列表 [参数]` | 管理员 | 分页浏览房间。别名 `/房间列表` `/铁锈房列表` `/rwlist` |
| `/铁锈下一页` `/铁锈上一页` | 管理员 | 房间列表翻页 |
| `/铁锈查房 <序号\|房号\|IP:端口>` | 管理员 | 显式查房。序号来自最近一次列表，房号如 `r5132` / `hytvvi`，也可直接填 `IP` 或 `IP:端口` |
| `/铁锈全局解析 开\|关` | 管理员 | 全局解析总开关，默认开 |
| `/铁锈模式 白\|黑\|混合` | 管理员 | 名单模式，默认黑。混合模式下 `@` 优先于 `#`，同名互斥 |
| `/铁锈白名 +@用户ID` `/铁锈白名 +#群号` | 管理员 | 白名单增删，无参数打印列表 |
| `/铁锈黑名 +@用户ID` `/铁锈黑名 +#群号` | 管理员 | 黑名单增删，无参数打印列表 |
| `/铁锈私聊策略 白\|黑` | 管理员 | 混合模式私聊默认策略 |
| `/铁锈私聊开关 开\|关` | 管理员 | 是否启用私聊查房，默认开 |
| `/铁锈玩家列表 开\|关` | 管理员 | 是否显示玩家列表，默认关 |
| `/铁锈重试 [0-10]` | 管理员 | 探针名被过滤时的重试次数 |
| `/铁锈撤回 开\|关\|[秒数0-300] [*]` | 群管理员 / 私聊所有人 | 自动撤回配置，按群/私聊独立保存。群聊加 `*` 对所有群生效，可被具体群覆盖；私聊不支持通配符 |
| `/铁锈查房调试` | 管理员 | 打印运行时状态：会话识别、撤回配置、探针池、列表缓存 |

发送未识别的 `/铁锈xxx` 时自动返回帮助菜单。

### 房间列表

```
/铁锈列表 [页码]|[筛选]|[搜索 关键词]|[刷新]
/铁锈下一页 / 铁锈上一页
```

**筛选词**

| 参数 | 说明 |
|------|------|
| `模组` / `原版` | 是否使用 Mod |
| `房间中` / `游戏中` | 房间状态 |
| `满` / `不满` | 人数是否已满 |
| `真人` / `官方` | 数据来源 |
| `搜索 关键词` | 按房主名 / 地图名模糊搜索 |
| `刷新` | 忽略缓存重新抓取 |

**页码**为纯数字，`2` 表示第 2 页。参数可任意组合，如 `/铁锈列表 模组 房间中 2` 表示「模组 + 房间中」筛选结果的第 2 页。

**筛选继承规则**

| 用法 | 行为 |
|------|------|
| `/铁锈列表`（不带参数） | 全新查询，清空所有筛选 |
| `/铁锈列表 2`（仅页码） | 沿用上次筛选，跳到第 2 页 |
| `/铁锈下一页` `/铁锈上一页` | 沿用上次筛选翻页 |
| `/铁锈列表 模组`（给了筛选词） | 整体替换旧筛选，只用本次条件 |

筛选状态按 QQ 号隔离，60 秒滑动过期。

展示格式（每页默认 5 条）：

```
1. 萧逸  1/10  房间中  原版
   地图：Crossing Large (10p)
   地址：Q23486

2. SERVER  2/10  房间中  原版
   地图：Two Sides Remake (10p)
   地址：3.19.39.252:5137
```

`地址` 就是该条可查房的目标：真人房（Q Room List）是房号（如 `Q23486`），
官方房是 `ip:port`。两者都能直接用在 `/铁锈查房` 里。

房名为 `Unnamed` 时优先展示房主名（CSV 第 1 列是房名，第 7 列才是房主名）。

### 查房

```
/铁锈查房 <序号|房号|IP:端口>
```

| 参数形式 | 说明 | 例子 |
|---|---|---|
| 序号 | 取自最近一次 `/铁锈列表` 的编号，60 秒内有效 | `/铁锈查房 2` |
| 数字房 | `o` `q` `r` `s` + 数字，至少 3 位 | `/铁锈查房 r5132` |
| 字母房 | 其他字母开头 + 纯字母，至少 3 位 | `/铁锈查房 hytvvi` |
| 直连 | `IP` 或 `IP:端口`（端口省略按 5123） | `/铁锈查房 45.76.27.30:5125` |

**权限**

`/铁锈列表` 与 `/铁锈查房` 都按黑白名单放行：默认 `black` 模式且名单为空时，
群里所有人都能用；管理员可用 `/铁锈模式`、`/铁锈白名`、`/铁锈黑名` 收窄范围。
被拦截时会明确回复原因，不会静默丢弃。

**自动触发与显式查房的区别**

| | 自动识别（群内发房号） | 显式查房（`/铁锈查房`） |
|---|---|---|
| 允许 IP 直连 | 否 | 是 |
| 查询失败 | **静默**，不发消息 | **回传原因** |
| 目的 | 避免英文单词误报刷屏 | 用户明确指定，必须给出结果 |

自动触发时只有「房间确实存在」类的原因才回传（房间已满 / 已锁定 / 游戏已开始 / 被封禁），
「房间不存在 / 中继未响应 / 地址不可达」等一律静默丢弃。

数据源两个，合并后真人房优先、房间中优先、人数降序：

| 源 | 说明 |
|----|------|
| Q Room List | `https://www.rtsbox.cn/api/paiwei/room_last.php`，真人房，含房主名 / 地图名 / 人数 / 状态 / 是否模组 |
| Official | 官方 `masterserver` 的完整列表（含 Auto Server 与中继房），排在真人房之后 |

列表只保留可查的真人房：链接条目、字段非法、空置入口、推广话术、
以及人数超出游戏上限（房间上限最大 100）的刷数据条目都会被跳过。

缓存：房间数据全局共享一份，翻页与筛选状态按 QQ 号隔离，均为 60 秒滑动过期，有操作就续期。

## 配置

由 AstrBot 框架自动持久化，可通过 WebUI 修改，也支持指令修改后即时保存。

| 配置项 | 说明 |
|--------|------|
| `global_enabled` | 全局解析开关，默认 true |
| `mode` | 名单模式：`white` / `black` / `mixed`，默认 black |
| `白名单` / `黑名单` | 白/黑名单列表（用户/群） |
| `混合_白名单` / `混合_黑名单` | 混合模式独立名单，切换回白/黑模式时原名单保持原状 |
| `混合_私聊策略` | 混合模式私聊默认策略：`white`=不在白名单拦截 / `black`=在黑名单拦截 |
| `私聊启用` | 是否启用私聊查房处理，默认 true |
| `debug` | 是否开启调试日志 |
| `max_players_display` | 玩家列表最多显示人数，超过则折叠，默认 10 |
| `show_players` | 是否显示玩家列表，默认 false |
| `retry_times` | 探针名被过滤时的重试次数，0-10，默认 3 |
| `list_page_size` | 房间列表每页条数，默认 5 |
| `list_max_display` | 房间列表最多展示的房间数，默认 20（0=不限）；超限时表头会提示实际命中总数 |
| `list_default_full` | 房间列表默认人数筛选，`hide` 表示隐藏人满房间 |
| `probe_max_per_msg` | 单条消息最多召唤的探针数，默认 5（1-20） |
| `bin_cleanup_enabled` | 是否在插件运行期间定时清理 bin 缓存，默认 true |
| `bin_cleanup_interval_hours` | 清理检查间隔（小时），默认 24 = 一天一次，最小 1 |
| `bin_cleanup_max_age_hours` | 只清理超过该小时数的 bin 缓存，默认 1 小时 |
| `群撤回` | 按群独立的撤回配置，格式 `#群号:开:延迟`，例 `#123456:1:60` |
| `私聊撤回` | 按用户独立的撤回配置，格式 `@用户ID:开:延迟`，例 `@3856554669:1:60` |

### bin 缓存清理

`room_info.py` 每次查到房间信息后，会把原始 106/115 报文写到
`server_info_<版本>_<目标>_<时间戳>.bin`，用于排查协议问题。这些文件只在调试时有用，
长期运行会不断堆积。

清理策略：**插件启动后开始计时，每隔 `bin_cleanup_interval_hours`（默认 24 小时）
检查一次，删除修改时间超过 `bin_cleanup_max_age_hours`（默认 1 小时）的 bin 文件。**

几个实现要点：

- 清理固定作用于 `room_info.py` 所在目录（`BIN_DIR`），不依赖当前工作目录；
  写入端也用同一路径，避免"写在 A 目录、清的是 B 目录"。
- 实际清理跑在独立子进程（`room_info.py --cleanup-bins`），不阻塞事件循环。
- 清理失败不会终止循环，下一轮会重试。
- 插件卸载（`terminate`）时会取消该循环，不留后台任务。
- 若加载时事件循环尚未就绪，会在首条消息到达时惰性补启，不影响正常使用。
- 间隔与阈值都有 60 秒下限保护，防止误配成 0 后疯狂执行。

也可以手动清理：

```bash
python3 room_info.py --cleanup-bins               # 清理 1 小时前的
python3 room_info.py --cleanup-bins --max-age 600 # 清理 10 分钟前的
```

## 消息示例

群内有人发：

```
ADMIN: Other players can type HLBIFZ in 'direct join' to connect to this room.
```

机器人自动回复：

```
版本：1.15
地图名称：Crossing Large (10p)
初始资金：4000¤[1x倍率]
初始禁核：未禁用核蛋蛋
初始迷雾：重雾
模式：遭遇战
默认单位：常规模式（1个建造者）
单位上限：1100
共享控制：否
允许旁观：是
队伍锁定：否
当前人数：2/10
使用Mod：原版（121 内置单位）
ID：hlbifz
 玩家列表:
  A1: abab
  A3: AI - Hard (AI)
```

探针名被过滤时先回进度再重试：

```
[房间查询] 重试中(1/3)
[房间查询] 重试中(2/3)
[房间查询] 重试中(3/3)
```

无法加入时返回翻译后的原因：

```
[房间查询失败] 房间已满，无法加入
[房间查询失败] 游戏已经开始
[房间查询失败] 房间已锁定
```

## 说明

- 查询通过子进程调用 `room_info.py` 完成，互不干扰，查询完自动发 111 退出，不占房间位置
- 私聊按发送者用户ID进名单校验；群聊同时校验 `#群号` 与 `@用户ID`（用户黑名单在群聊同样生效）
- 玩家列表按槽位顺序显示，空名字显示为 `(空)`
- 房间处于「开局后返回战役室」状态时服务器不更新状态，此时真人可进入但探针会被拒绝，属游戏机制
- 本插件仅供学习与娱乐，请勿用于恶意刷房或干扰他人游戏
